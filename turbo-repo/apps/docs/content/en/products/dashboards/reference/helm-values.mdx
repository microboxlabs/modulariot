# Helm values

Values of the `miot-dashboard-server` chart, version 0.1.2. Each value that sets an environment variable names it. Settings without a value go in `extraEnv` or `extraEnvFrom`.

## Workload

| Value | Default | Meaning |
| --- | --- | --- |
| `replicaCount` | `1` | Keep 1 with SQLite |
| `strategy.type` | `Recreate` | `Recreate` stops the old pod first, so two pods never share a SQLite file |
| `image.repository` | `ghcr.io/microboxlabs/miot-dashboard-server` | Image |
| `image.tag` | `latest` | Pin a `sha-<commit>` tag |
| `image.pullPolicy` | `Always` | Use `IfNotPresent` with a pinned tag |
| `resources` | `{}` | CPU and memory requests and limits |
| `podSecurityContext` | `fsGroup: 1001` | |
| `securityContext` | non-root UID 1001, read-only root, no privilege escalation, all capabilities dropped | |
| `nodeSelector`, `tolerations`, `affinity` | empty | Scheduling |
| `volumes`, `volumeMounts` | empty | Extra mounts, such as a read-only query module |
| `extraEnv`, `extraEnvFrom` | empty | Any other environment variable or secret |

## Secrets

Every sensitive value accepts either a literal, which the chart stores in a Secret it manages, or `existingSecret` and `existingSecretKey`, which point at a Secret you created. Use `existingSecret` in production, so secrets stay out of values files.
