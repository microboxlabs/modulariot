# Changelog

Version history and release notes for ModularIoT.

## Version Format

We follow semantic versioning: `MAJOR.MINOR.PATCH`

- **MAJOR** - Breaking changes
- **MINOR** - New features, backward compatible
- **PATCH** - Bug fixes, backward compatible

## Upcoming

Features and improvements in development:

- JavaScript, Python, and Java SDKs
- Advanced symptom patterns
- Enhanced notification channels
- Historical analytics dashboard

## Lanzamientos Recientes

### UI de dashboards v0.1.1 (2026-10-07)

Se publicó la [UI de dashboards](https://www.npmjs.com/package/@microboxlabs/miot-dashboard-ui) v0.1.1:

- En modo edición, un widget se puede arrastrar desde cualquier punto, incluso desde el centro de una tabla o un gráfico. Mientras la grilla permite arrastrar, el contenido del widget ya no se desplaza, no toma el puntero y no selecciona texto. Los controles del `Frame` del host y los widgets contenedores siguen respondiendo.

### Servidor de dashboards v0.7.0 (2026-10-06)

Se publicó el [servidor](https://www.npmjs.com/package/@microboxlabs/miot-dashboard-server) v0.7.0:

- `MIOT_DASHBOARD_GROUP_ROLES_PATTERN` y `MIOT_DASHBOARD_GROUP_ROLES_MAP` leen los roles de organización y ámbito desde los grupos de quien llama, como `GROUP_DHB_{tenant}_{role}`, sin archivo semilla ni servicio de consulta ([guía](/es/products/dashboards/how-to/authenticate-users)). `createGroupRoleAuthorities` hace lo mismo para quienes usan la biblioteca. Requiere el contrato `^0.6.0`.

### Paquetes de dashboards v0.6.0 y UI de dashboards v0.1.0 (2026-10-05)

[Contrato](https://www.npmjs.com/package/@microboxlabs/miot-dashboard-contract) y [servidor](https://www.npmjs.com/package/@microboxlabs/miot-dashboard-server) v0.6.0 publicados, y primera versión de la [UI de dashboards](https://www.npmjs.com/package/@microboxlabs/miot-dashboard-ui), v0.1.0:

- Contrato v0.6.0: los filtros pueden declarar selección única (`single`) y tomar sus opciones del resultado de una consulta guardada (`optionsSource`). El documento OpenAPI agrega la ruta del catálogo de consultas, y los resúmenes de la lista incluyen el `order` del dashboard.
- Servidor v0.6.0: un proveedor opcional de catálogo muestra a los editores las conexiones, operaciones y columnas aprobadas, sin credenciales. `createRemoteQueryCatalog` lo lee desde un endpoint del host. Las listas se ordenan por `order`. `plannerOperationContracts` y `migratePlannerQueries` convierten dashboards con planificador en consultas guardadas ([guía](/es/products/dashboards/how-to/migrate-planner-dashboards)). Requiere el contrato `^0.6.0`.
- UI v0.1.0, primera versión: renderizado del catálogo de dashboards en React, Web Component y navegador sin framework, y edición de configuración, consultas guardadas, permisos, filtros e importación/exportación. `useDashboardAutosave` guarda el documento cuando se detienen las ediciones. Requiere el contrato `^0.6.0`; React 18 o 19 y ECharts 6 son dependencias peer.

### Paquetes de dashboards v0.5.0 — Permisos de creación (2026-09-29)

[Contrato](https://www.npmjs.com/package/@microboxlabs/miot-dashboard-contract) y [servidor](https://www.npmjs.com/package/@microboxlabs/miot-dashboard-server) compatibles v0.5.0 publicados:

- Nuevo endpoint de capacidades del ámbito y método embebido para consultar si se puede iniciar la creación sin leer documentos. Los tokens de embed no pueden usarlo.
- Al crear un dashboard se aplican tanto el límite de edición de la credencial como la política del documento. Contributor conserva la creación con la política predeterminada.
- El servidor requiere el contrato `^0.5.0` para mantener el OpenAPI instalado alineado con el runtime.

Una instalación nueva desde npm validó las 11 exportaciones y los permisos del servidor independiente con SQLite/JWT. Despliegue primero el servidor, después el proxy del host y finalmente el espacio de trabajo. La publicación no completa la aceptación de Consumer en navegador ni la migración de telemetría.

### Paquetes de dashboards v0.4.0 — Herramientas de migración (2026-09-29)

Contrato y servidor compatibles v0.4.0 publicados:

- Validar documentos importados con el contrato compartido antes de acceder al almacén, incluso en simulaciones.
- Convertir solicitudes del planner mediante mapas explícitos de conexión/operación, conservando vínculos de widgets y configuración.
- Usar `omitWhenEmpty` para argumentos de filtros opcionales, conservando el comportamiento anterior y el control de tenant del host.
- El servidor standalone aplica `allowedGroups`; configure grupos confiables por JWT o ticket antes de actualizar dashboards restringidos.

Actualizar ambos paquetes juntos. Estas herramientas no sustituyen la aceptación de datos, filtros y permisos reales.

[server v0.4.0](https://www.npmjs.com/package/@microboxlabs/miot-dashboard-server/v/0.4.0) | [contract v0.4.0](https://www.npmjs.com/package/@microboxlabs/miot-dashboard-contract/v/0.4.0)

### Paquetes de dashboards v0.3.0 — Ejecución portable (2026-09-29)

Publicados `@microboxlabs/miot-dashboard-server` y `@microboxlabs/miot-dashboard-contract` v0.3.0. Ambos paquetes están disponibles en npm; la aceptación de la migración en dev sigue pendiente.

- El contrato incorpora consultas basadas en conexiones con límites y filtros identificados por nombre, manteniendo compatibilidad con documentos de versión 2.
- El servidor exporta ejecutores TypeScript para BigQuery y HTTP de solo lectura en `/queries`, con aislamiento de tenant, plazos, cancelación y límites de costo y respuesta.
- Los hosts embebidos aportan un adaptador confiable. La imagen standalone incluye un módulo para el catálogo privado de ModularIoT; ejecutar consultas no requiere Java ni Alfresco.
- Actualizar ambos paquetes juntos. Los despliegues standalone existentes deben configurar explícitamente un módulo de operaciones para habilitar consultas guardadas portables.

Consultar la [guía de consultas](/es/products/dashboards/concepts/queries-and-connections) y la [hoja de ruta de aceptación](/es/products/dashboards/releases).

**`@microboxlabs/miot-calendar-client`** — [npm](https://www.npmjs.com/package/@microboxlabs/miot-calendar-client) | [GitHub](https://github.com/microboxlabs/modulariot/tree/trunk/packages/miot-calendar-client)

### `miot-calendar-client` v0.3.0 — Gestores de Slots (2026-02-20)

**`@microboxlabs/miot-calendar-client`** — [npm](https://www.npmjs.com/package/@microboxlabs/miot-calendar-client) | [GitHub](https://github.com/microboxlabs/modulariot/tree/trunk/packages/miot-calendar-client)

Agrega un nuevo recurso de Gestores de Slots para automatizar la generación de slots. Cada gestor mantiene los slots generados un número configurable de días por adelantado y puede activarse manualmente o mediante un planificador externo.

**Nuevo — namespace `client.slotManagers`:**
- `slotManagers.list({ active? })` — listar todos los gestores de slots
- `slotManagers.create(body)` — crear un gestor para un calendario
- `slotManagers.get(id)` — obtener un gestor por ID
- `slotManagers.update(id, body)` — actualizar configuración (incluyendo reprocesamiento puntual)
- `slotManagers.deactivate(id)` — desactivar un gestor (eliminación lógica)
- `slotManagers.runAll()` — ejecutar todos los gestores activos sincrónicamente
- `slotManagers.run(id)` — ejecutar un gestor individual
- `slotManagers.listAllRuns({ limit? })` — listar ejecuciones recientes de todos los gestores
- `slotManagers.listRuns(id, { limit? })` — listar ejecuciones de un gestor específico

**Nuevos tipos exportados:** `SlotManagerRequest`, `SlotManagerResponse`, `SlotManagerRunResponse`

### `miot-calendar-client` v0.2.0 — Grupos de Calendarios (2026-02-19)

**`@microboxlabs/miot-calendar-client`** — [npm](https://www.npmjs.com/package/@microboxlabs/miot-calendar-client) | [GitHub](https://github.com/microboxlabs/modulariot/tree/trunk/packages/miot-calendar-client)

Agrega un nuevo recurso de Grupos de Calendarios que permite organizar calendarios en colecciones con nombre y filtrarlos o consultarlos por grupo.

**Nuevo — namespace `client.groups`:**
- `groups.list({ active? })` — listar todos los grupos
- `groups.get(id)` — obtener un grupo por ID
- `groups.create(body)` — crear un grupo
- `groups.update(id, body)` — actualizar un grupo
- `groups.deactivate(id)` — desactivar un grupo (eliminación lógica)

**Actualizado — `client.calendars`:**
- `calendars.list()` acepta el nuevo parámetro `groupCode` para filtrar calendarios por pertenencia a un grupo
- `CalendarRequest.groups?: string[]` — asigna grupos al crear o actualizar (`null` = sin cambios, `[]` = eliminar todos, `["code"]` = reemplazar todos)
- `CalendarResponse.groups?: CalendarGroupResponse[]` — los grupos a los que pertenece el calendario ahora se incluyen en la respuesta

**Nuevos tipos exportados:** `CalendarGroupRequest`, `CalendarGroupResponse`

### Arquitectura: Navegación Lateral Centralizada (2026-02-19)

**`apps/app` — cambio interno, sin impacto en la API**

La navegación de la barra lateral fue refactorizada para usar un único contexto compartido `SidebarNavigationProvider` por encima de los componentes de barra lateral de escritorio y móvil.

**Qué cambió para los operadores:**
- Los contadores de la barra lateral de escritorio y móvil ahora están garantizados para ser idénticos — anteriormente podían divergir porque cada barra lateral obtenía datos independientemente
- Los elementos de filtros de usuario bajo la sección de Tareas ya no se duplican después de navegar entre páginas

**Qué cambió para los desarrolladores:**
- Todos los datos de navegación (contadores, elementos de filtros de tareas dinámicos) se obtienen una vez por carga de página en lugar de dos veces
- La constante del módulo `pages.ts` ya no es mutada en tiempo de ejecución
- Las nuevas secciones con sub-elementos dinámicos pueden agregarse mediante `dynamicItemsSource` + un hook dedicado — ver [Extender la Navegación](/reference/frontend-architecture/extending-navigation)

Ver [ADR-001](/reference/architecture-decisions/adr-001-sidebar-navigation-context) para el registro completo de la decisión.
