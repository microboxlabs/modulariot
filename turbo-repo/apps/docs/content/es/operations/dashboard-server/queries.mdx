# Consultas basadas en conexiones

Una consulta guardada identifica una conexión y operación del host mediante `connectionId` y `operationId`. Los lectores seleccionan la consulta por ID y envían valores de filtros. No pueden enviar una URL, SQL, credenciales ni otra operación. El mismo servidor puede integrarse con distintos frameworks y herramientas de administración.

```json
{
  "id": "costs",
  "variableName": "costs",
  "connectionId": "billing",
  "operationId": "cost-summary",
  "parameters": {
    "days": { "kind": "literal", "value": 30 },
    "service": { "kind": "filter", "key": "service", "defaultValue": null }
  }
}
```

## Integración de la biblioteca

`createDashboardQueryService` recibe los adaptadores de identidad, tenant, ámbito, almacenamiento y políticas del control de acceso, además de un `DashboardOperationExecutor`. El host llama a `service.execute(request, ref, queryId, filters, signal)`. En un host HTTP, pasa una función asíncrona como `filters` para leer el cuerpo después de autorizar. Este servicio programático no registra una ruta HTTP automáticamente.

La autorización ocurre antes de cargar o ejecutar una consulta. Un Consumer puede consultar un dashboard al que tiene acceso; las identidades embed siguen limitadas a su dashboard exacto. Se rechazan IDs desconocidos, definiciones ambiguas, valores inválidos y filtros no declarados. Las decisiones de acceso usan el evento `dashboard.query`, sin incluir valores de filtros ni filas.

## Responsabilidades del host

El adaptador debe resolver una **operación activa y de solo lectura dentro del tenant autorizado**, validar sus parámetros, aplicar las restricciones del tenant y resolver las credenciales en el servidor. Las definiciones son editables: un parámetro literal no acredita autoridad sobre un tenant. Mantén las restricciones de seguridad fuera de los parámetros editables.

Limita las lecturas de respuestas antes de cargarlas en memoria. Respeta la señal de cancelación y aplica límites propios del origen, incluidos los costos de BigQuery. Devuelve `{ rows: [...] }` con valores escalares JSON o arreglos planos de escalares. No incluyas credenciales ni errores internos en los resultados.

## Límites de ejecución

Por defecto: 8 operaciones simultáneas por instancia, 20 segundos, 5.000 filas y 2 MiB de JSON UTF-8. Cada fila admite hasta 100 campos. Los valores siguen los límites del contrato; se admiten hasta 32 filtros y 100 parámetros por definición. Configura `maxConcurrent`, `timeoutMs`, `maxRows` y `maxBytes` al crear el servicio.

Un timeout cancela la señal del adaptador. Si el adaptador ignora la cancelación, mantiene su cupo hasta terminar, evitando trabajo ilimitado en segundo plano. Los fallos y resultados inválidos se convierten en `UPSTREAM_ERROR`. Estos límites complementan la autenticación, el tamaño máximo del cuerpo HTTP y los límites de solicitudes del despliegue.

## Política de operaciones de ModularIoT

El módulo de integraciones ofrece `DashboardOperationPolicy.prepare` para los
adaptadores del host. Primero resuelve una **conexión ACTIVE del tenant
autorizado**. El helper valida la operación guardada e incorpora el código del
tenant del host; no autoriza la conexión ni ejecuta solicitudes de red.

Las operaciones se habilitan mediante `requestSchema["x-dashboard"]`:

```json
{
  "type": "object",
  "properties": {
    "days": { "type": "integer", "minimum": 1, "maximum": 30 },
    "tenant": { "type": "string" }
  },
  "required": ["days", "tenant"],
  "additionalProperties": false,
  "x-dashboard": {
    "readOnly": true,
    "kind": "HTTP_GET",
    "tenantParameter": "tenant"
  }
}
```

`HTTP_GET` exige una operación GET; `BIGQUERY` exige POST y un ejecutor específico
de BigQuery. El cliente no puede enviar `tenantParameter`, aunque su valor sea
correcto. El host lo agrega antes de validar el esquema. Si las credenciales ya
aíslan la cuenta de origen, un administrador puede declarar
`credentialScoped: true` y omitir `tenantParameter`. El administrador debe
verificar que la operación sea de solo lectura; usar GET no lo garantiza.

El esquema debe describir un objeto cerrado (`additionalProperties: false`).
Se admite Draft 2020-12 sin referencias locales/remotas ni reglas regex. Se
limitan tamaño, profundidad y cantidad de nodos; los validadores compilados usan
una caché acotada. Los parámetros admiten escalares JSON y arreglos planos con
los mismos límites de valores del contrato y un máximo de 256 KiB en el host.
