# Dashboard UI

`@microboxlabs/miot-dashboard-ui` renderiza documentos de dashboard en React y otros frameworks web usando el contrato compartido.

**Estado: candidato del workspace sin publicar.** Compile el paquete o use un tarball candidato; estas APIs no implican que exista una versión publicada en npm.

## Elegir una integración

- **React y Next.js:** use la entrada React para renderizado, estado del documento, filtros y proveedores de consultas guardadas. Mantenga la sesión y las credenciales del servidor en el backend del host.
- **HTML u otro framework:** use el runtime de navegador autocontenido con `mountDashboard`. Actualice la instancia cuando cambie el estado del host y destrúyala al retirar su contenedor.
- **Web Components y LiveView:** registre explícitamente el elemento personalizado y pase su configuración mediante la propiedad JavaScript. Excluya el contenedor de montaje de los parches DOM del host y límpielo en su ciclo de vida.

El runtime de navegador incluye sus dependencias de renderizado; el host no necesita instalar React. Cargue una vez la hoja de estilos del paquete. El host puede personalizar las variables de tema documentadas.

## Capacidades implementadas

El paquete incluye registro de widgets, primitivas de grilla/canvas, renderizadores de texto, porcentaje y estadísticas circulares y de progreso, plantillas, filtros y resultados de consultas guardadas. Las consultas admiten cancelación y concurrencia limitada. El estado del documento conserva revisiones y borradores después de conflictos.

Los registros portables admiten datos estáticos, valores de plantillas/proveedores y resultados de consultas guardadas con nombre. Las configuraciones de datasource directo requieren migración a conexiones y consultas guardadas del servidor. Estos registros no constituyen el catálogo completo de widgets, configuraciones ni backoffice de la app.

Los controles de filas para tablas y listas ofrecen filtrado y ordenamiento numérico por instancia sobre resultados autorizados, sin modificar las filas originales.

Las barras controladas de filtros y ordenamiento exponen selección, dirección traducida y controles de teclado, con estilos claros y oscuros acotados.

El contenido portable de celdas admite texto literal y multilínea, badges, números con signo y progreso accesible, con reglas de color seguras.

Los helpers de plantillas de columnas compilan claves, encabezados y tipos dinámicos de celda con motores aislados y contexto de fila y cantidad.

Los filtros tipados de columnas admiten texto, números, fechas, enums y booleanos, con detección de tipos y selecciones combinadas.

El resumen de filtros activos ofrece botones accesibles para eliminar filtros, limpiar todos y textos y formatos proporcionados por el host.

Los editores portables ofrecen texto y números con actualización diferida, rangos de fechas, casillas nativas con búsqueda y grupos de opciones booleanas aislados. El host proporciona traducciones y gestiona el popover.

El popover portable de filtros gestiona foco, cierre con Escape o interacción exterior y posición en la ventana, con contenedor y tema elegidos por el host.

Los modelos compartidos normalizan acciones de tablas/listas y restringen protocolos, incluidas URLs ejecutables ofuscadas. El host valida las plantillas resueltas y conserva la autorización del destino.

## Ejecutar el ejemplo embebido

El [ejemplo standalone](https://github.com/microboxlabs/modulariot/tree/trunk/turbo-repo/examples/dashboard-ui-standalone) incluye un host de navegador y un proxy Node. Muestra resultados de facturación desde un servidor de dashboards configurado y permite seleccionar servicios, actualizar y buscar en una tabla del host.

Su README explica cómo preparar los archivos del paquete compilado, configurar el servidor y la identidad Consumer, y montar los archivos privados de acceso y firma. La tabla y el resumen pertenecen al ejemplo; los tres widgets embebidos provienen de la biblioteca.

Los borradores de acciones incompletos siguen siendo editables. Las posiciones de fila inválidas quedan vacías sin promover acciones secundarias; el renderizador valida los destinos resueltos.

## Límite de seguridad

El servidor aplica permisos de tenant, scope y documento. Nunca incluya claves de firma, credenciales de base de datos ni claves de cuenta de servicio en la configuración del navegador. El proxy del ejemplo permite únicamente las lecturas configuradas; es un acceso privado para demostración, no SSO de producción.

El compilador actual de Handlebars requiere `unsafe-eval` en la CSP de scripts. Evalúe esta restricción antes de integrar en un host con CSP estricta. No se afirma compatibilidad con CSP estricta.
