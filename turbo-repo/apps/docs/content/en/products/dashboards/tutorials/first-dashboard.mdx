# Build your first dashboard

**For:** implementers. **Setup:** ModularIoT (the web app at modulariot.com/app).

<Callout type="info">
**You will learn to:**

- create a dashboard and add a widget;
- write a SQL query that returns one row with a number per state;
- show those numbers in a Stacked Stat (KPI per state + 100% bar);
- show the detail in a table;
- filter the table with a select filter;
- share the dashboard.
</Callout>

The result is a dashboard of requests: at the top, how many are in each state; below, the list. It takes about 30 minutes.

## Before you start

| You need | Why | If you do not have it |
| --- | --- | --- |
| **Dashboards** in the navigation | It is where dashboards are created | Ask an administrator to turn it on ([Deploy with ModularIoT](/en/products/dashboards/deployment/with-modulariot)) |
| The **Contributor** organization role or higher | Consumers can only view dashboards | Ask an administrator for the role |
| A BigQuery connection with a service account | To write the SQL queries | Steps 1 and 2 work without it. See [Connect BigQuery](/en/products/dashboards/how-to/connect-bigquery) |

The example uses a `solicitudes` (requests) table with these columns. Replace the names with your table's.

| Column | Type | Example |
| --- | --- | --- |
| `id` | STRING | `S-1042` |
| `estado` (state) | STRING | `pendiente`, `en_curso`, `cerrada` |
| `responsable` (owner) | STRING | `North team` |
| `creada_en` (created at) | TIMESTAMP | `2026-10-01 09:30:00` |

<Steps>

### Create the dashboard

1. Open **Dashboards** in the navigation.
2. Select **Create Dashboard**.
3. In **Name**, type `Requests` and select **Create**.

The dashboard opens empty. Changes save on their own a few seconds after each edit.

### Add a Stacked Stat with fixed data

Start with numbers typed by hand. You see the widget before you connect data.

1. Turn on **Edit Mode** at the top of the dashboard.
2. Select **Add Widget** and choose **Stacked Stat**.
3. Hover over the widget and open its settings (the gear).
4. In the **Visualization** tab:
   - **Title**: `Requests by state`.
   - **Unit**: leave it empty. The default is `%`.
   - **Categories**: delete the four sample categories. Select **Add** three times and fill in:

     | Label | Value | Color |
     | --- | --- | --- |
     | `Pending` | `12` | yellow |
     | `In progress` | `7` | blue |
     | `Closed` | `30` | green |

5. Save the settings.

The widget shows a bar split in three parts, proportional to 12, 7 and 30, and a legend with each number.

<Callout type="warning">
**Pitfall:** the default **Unit** is `%`. If you do not clear it, the legend shows `12%`.
</Callout>

### Write the summary query

A Stacked Stat reads **one row**: the first row the query returns. Each category reads one column of that row. So the query turns the states (rows) into columns.

1. Go to **Settings › Connections** and open the **BigQuery** section.
2. Choose your connection and select **New**.
3. Write the query:

   ```sql
   SELECT
     COUNT(*) AS total,
     SUM(CASE WHEN estado = 'pendiente' THEN 1 ELSE 0 END) AS pendiente,
     SUM(CASE WHEN estado = 'en_curso'  THEN 1 ELSE 0 END) AS en_curso,
     SUM(CASE WHEN estado = 'cerrada'   THEN 1 ELSE 0 END) AS cerrada
   FROM `my-project.operations.solicitudes`
   ```

4. Select **Run**. You should see one row:

   | total | pendiente | en_curso | cerrada |
   | --- | --- | --- | --- |
   | 49 | 12 | 7 | 30 |

5. Open **Query settings**, type the name `resumen_estados` and select **Save**.

Only `SELECT` queries can be saved. The editor shows how many bytes the query will read before you run it.

### Connect the widget to the query

A dashboard uses a query through a **saved query**: a short name that widgets choose.

1. Go back to the dashboard. With **Edit Mode** on, open the dashboard settings menu (the gear in the header) and choose **Saved queries**.
2. Select **Add query** and fill in:
   - **Result name**: `resumen`.
   - **Connection**: your BigQuery connection.
   - **Operation**: `resumen_estados`.
   - **Parameters (JSON)**: `{}`.
3. Select **Apply to draft**.
4. Open the Stacked Stat settings. In the **Data Provider** tab, set **Data Source** to **Planner** and choose `resumen` in **Variable**. The available columns appear below: `total`, `pendiente`, `en_curso`, `cerrada`.
5. In the **Visualization** tab, replace each category value with a template that names the column:

   | Label | Value |
   | --- | --- |
   | `Pending` | `{{pendiente}}` |
   | `In progress` | `{{en_curso}}` |
   | `Closed` | `{{cerrada}}` |

6. Change **Title** to `Requests by state ({{total}})` and save.

The widget shows the real numbers. `{{column}}` is replaced by that column's value in the first row.

<details>
<summary>Why "Planner"</summary>

**Planner** is the UI's name for the dashboard's saved queries. **Static (JSON)** uses data typed into the widget. **PGREST** calls a PostgREST function directly from the widget, without a saved query.

</details>

### Add the detail table

A table reads **all the rows** of its query. One query row is one table row.

1. In **Settings › Connections › BigQuery**, create another query, `detalle_solicitudes`:

   ```sql
   SELECT id, estado, responsable, creada_en
   FROM `my-project.operations.solicitudes`
   WHERE (IFNULL(@estado, '') = '' OR estado = @estado)
   ORDER BY creada_en DESC
   LIMIT 500
   ```

2. In **Parameters**, declare `estado` with type `STRING`. Leave **Test value** empty and run: the query receives `NULL`, `IFNULL` treats it as empty, and all states come back. Type `en_curso` and run again: only those rows come back. Save.
3. In the dashboard, add a saved query:
   - **Result name**: `detalle`.
   - **Operation**: `detalle_solicitudes`.
   - **Parameters (JSON)**:

     ```json
     { "estado": { "kind": "filter", "key": "estado", "defaultValue": "" } }
     ```

4. Select **Add Widget** and choose **Data Table V2**.
5. In its settings, **Data Provider** tab, set **Data Source** to **Planner** and **Variable** to `detalle`. The table columns are filled in from the query.
6. In **Columns**, change the labels: `ID`, `State`, `Owner`, `Created`. Save.

`@estado` is a BigQuery parameter. The binding `{"kind": "filter", "key": "estado"}` gives it the value of the `estado` filter, which you create in the next step. While the filter is empty, the server sends `defaultValue` (`""`), and the condition `IFNULL(@estado, '') = ''` lets every row through.

<Callout type="warning">
**Pitfall:** a BigQuery query always receives all its parameters. Do not use `omitWhenEmpty` with BigQuery: if the parameter is left out, the query fails. Use `defaultValue`.
</Callout>

### Filter the table by state

1. Open the dashboard settings menu and choose **Filter Bar**.
2. Select **Add filter** and fill in:
   - **Filter key**: `estado`. It must match `key` in the query binding.
   - **Display label**: `State`.
   - **Control type**: **Selection**.
   - **Static options**: `Pending` / `pendiente`, `In progress` / `en_curso`, `Closed` / `cerrada`.
   - Turn on **Allow a single selection**.
3. Select **Apply filters to draft**.

Choose **In progress** in the filter bar. The table reloads and shows only those rows. The Stacked Stat does not change: its query has no parameter bound to `estado`.

<Callout type="info">
Clicking a part of the Stacked Stat bar does not filter the table. The filter bar is the way to do it.
</Callout>

### Share the dashboard

1. Turn off **Edit Mode**.
2. Open the settings menu and select **Manage permissions**.
3. Find your colleague under **Users**, choose the **Reader** role and select **Add**.

Your colleague can open the dashboard and use the filter, but cannot change it. To let them edit, give them **Editor**.

</Steps>

## What you built

| Piece | Reads | Query shape |
| --- | --- | --- |
| Stacked Stat | The first row of `resumen` | One row, one column per state |
| Data Table V2 | All rows of `detalle` | One row per request |
| `estado` filter | — | Gives a value to the `@estado` parameter |
