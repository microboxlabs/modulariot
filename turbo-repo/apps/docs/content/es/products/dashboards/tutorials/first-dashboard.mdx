# Construir su primer dashboard

**Para:** implementadores. **Configuración:** ModularIoT (la aplicación web en modulariot.com/app).

<Callout type="info">
**Aprenderá a:**

- crear un dashboard y agregar un widget;
- escribir una consulta SQL que devuelve una fila con un número por estado;
- mostrar esos números en un Stacked Stat (KPI por estado + barra 100 %);
- mostrar el detalle en una tabla;
- filtrar la tabla con un filtro de selección;
- compartir el dashboard.
</Callout>

El resultado es un dashboard de solicitudes: arriba, cuántas hay en cada estado; abajo, la lista. Toma unos 30 minutos.

## Antes de empezar

| Necesita | Por qué | Si no lo tiene |
| --- | --- | --- |
| Ver **Dashboards** en la navegación | Es donde se crean los dashboards | Pida a un administrador que lo active ([Desplegar con ModularIoT](/es/products/dashboards/deployment/with-modulariot)) |
| Rol de dashboards **Contributor** o superior ([roles](/es/products/dashboards/concepts/access-model)) | Con el rol Consumer solo puede ver dashboards | Pida el rol a un administrador |
| Rol **Owner** de la organización, para guardar consultas SQL | Los administradores pueden leer y ejecutar consultas, no guardarlas | Pida a un Owner que guarde las consultas de los pasos 3 y 5 |
| Una conexión de BigQuery con una cuenta de servicio | Para escribir las consultas SQL | Los pasos 1 y 2 funcionan sin ella. Vea [Conectar BigQuery](/es/products/dashboards/how-to/connect-bigquery) |

El ejemplo usa una tabla `solicitudes` con estas columnas. Cambie los nombres por los de su tabla.

| Columna | Tipo | Ejemplo |
| --- | --- | --- |
| `id` | STRING | `S-1042` |
| `estado` | STRING | `pendiente`, `en_curso`, `cerrada` |
| `responsable` | STRING | `Equipo norte` |
| `creada_en` | TIMESTAMP | `2026-10-01 09:30:00` |

<Steps>

### Crear el dashboard

1. Abra **Dashboards** en la navegación.
2. Seleccione **Crear Dashboard**.
3. En **Nombre**, escriba `Solicitudes` y seleccione **Crear**.

El dashboard se abre vacío, con el botón **Add Widget** en el centro. Los cambios se guardan solos unos segundos después de cada edición.

### Agregar un Stacked Stat con datos fijos

Empiece con números escritos a mano para ver el widget antes de conectar datos.

1. Seleccione **Add Widget**, escriba `Stacked` en el buscador y elija **Stacked Stat**. El widget aparece con datos de ejemplo ("Traffic Sources").
2. Active **Modo Edición** en la parte superior derecha. Desde ahora, el botón para agregar widgets se llama **Agregar Widget** y está bajo la grilla.
3. Pase el cursor sobre el widget y abra sus ajustes (el engranaje).
4. En la pestaña **Visualización**:
   - **Tipo de gráfico**: **Barra**. **Dona** dibuja un anillo con las mismas partes.
   - **Título**: `Solicitudes por estado`.
   - **Unidad**: borre el `%` que trae por defecto.
   - **Categories**: el widget trae cuatro categorías de ejemplo. Cambie las tres primeras y borre la cuarta con el ícono de papelera. El color se elige con el círculo de color de cada fila:

     | Etiqueta | Valor | Color |
     | --- | --- | --- |
     | `Pendiente` | `12` | amarillo |
     | `En curso` | `7` | azul |
     | `Cerrada` | `30` | verde |

5. Seleccione **Guardar**, al pie del panel.

El widget muestra una barra dividida en tres partes, proporcionales a 12, 7 y 30, y una leyenda con cada número. El widget no cambia mientras edita sus ajustes; el cambio se ve al guardar.

<Callout type="warning">
**Cuidado:** si no borra el `%` de **Unidad**, la leyenda muestra `12%`. Algunos ajustes del Stacked Stat (**Show Header**, **Categories**, **Add**) aparecen en inglés en la interfaz en español. La tecla Esc no cierra el selector de color: abre el aviso de cambios sin guardar. Elija **Seguir editando**.
</Callout>

### Escribir la consulta del resumen

Un Stacked Stat lee **una sola fila**: la primera que devuelve la consulta. Cada categoría lee una columna de esa fila. Por eso la consulta convierte los estados (filas) en columnas.

1. Vaya a **Ajustes › Conexiones** y abra **BigQuery**, en **Editores**.
2. Elija su conexión en **Conexión** y seleccione **+ Nueva**.
3. Escriba la consulta:

   ```sql
   SELECT
     COUNT(*) AS total,
     SUM(CASE WHEN estado = 'pendiente' THEN 1 ELSE 0 END) AS pendiente,
     SUM(CASE WHEN estado = 'en_curso'  THEN 1 ELSE 0 END) AS en_curso,
     SUM(CASE WHEN estado = 'cerrada'   THEN 1 ELSE 0 END) AS cerrada
   FROM `mi-proyecto.operaciones.solicitudes`
   ```

4. Seleccione **Ejecutar**. Debe ver una fila:

   | total | pendiente | en_curso | cerrada |
   | --- | --- | --- | --- |
   | 49 | 12 | 7 | 30 |

5. En **Ajustes de la consulta**, debajo del editor, cambie **Nombre** a `resumen_estados` y seleccione **Guardar**.

Solo se pueden guardar consultas `SELECT`. Bajo el editor, **Leerá** indica cuántos bytes leerá la consulta. Una consulta guardada aquí aparece de inmediato como **Operación** de esa conexión en los dashboards de la organización.

<Callout type="info">
**Probar sin una tabla propia.** Reemplace el `FROM` por esta tabla de ejemplo. Genera 49 solicitudes y lee 0 bytes:

```sql
WITH solicitudes AS (
  SELECT
    FORMAT('S-%04d', n) AS id,
    CASE WHEN n <= 12 THEN 'pendiente' WHEN n <= 19 THEN 'en_curso' ELSE 'cerrada' END AS estado,
    CASE MOD(n, 3) WHEN 0 THEN 'Equipo norte' WHEN 1 THEN 'Equipo sur' ELSE 'Equipo centro' END AS responsable,
    TIMESTAMP_SUB(TIMESTAMP '2026-10-30 12:00:00', INTERVAL n * 7 HOUR) AS creada_en
  FROM UNNEST(GENERATE_ARRAY(1, 49)) AS n
)
SELECT
  COUNT(*) AS total,
  SUM(CASE WHEN estado = 'pendiente' THEN 1 ELSE 0 END) AS pendiente,
  SUM(CASE WHEN estado = 'en_curso'  THEN 1 ELSE 0 END) AS en_curso,
  SUM(CASE WHEN estado = 'cerrada'   THEN 1 ELSE 0 END) AS cerrada
FROM solicitudes
```

Use el mismo `WITH solicitudes AS (…)` al inicio de la consulta de detalle del paso 5.
</Callout>

### Conectar el widget a la consulta

Un dashboard usa una consulta por medio de una **consulta guardada**: un nombre corto que los widgets eligen.

1. Vuelva al dashboard. Con **Modo Edición** activo, abra el menú de ajustes del dashboard (el engranaje junto a **Modo Edición**) y elija **Consultas guardadas**.
2. Seleccione **Agregar consulta** y complete:
   - **Nombre del resultado**: `resumen`.
   - **Conexión**: su conexión de BigQuery.
   - **Operación**: `resumen_estados`.
   - **Parámetros (JSON)**: `{}`.
3. Seleccione **Aplicar al borrador**. Esto agrega la consulta al dashboard. El dashboard se guarda solo; no hay un paso de publicación. Cierre el menú haciendo clic fuera de él.
4. Abra los ajustes del Stacked Stat. En la pestaña **Proveedor de Datos**, fije **Fuente de Datos** en **Planificador** y elija `resumen` en **Variable**. Debajo aparecen las columnas disponibles: `total`, `pendiente`, `en_curso`, `cerrada`.
5. En la pestaña **Visualización**, cambie el valor de cada categoría por una plantilla con el nombre de la columna:

   | Etiqueta | Valor |
   | --- | --- |
   | `Pendiente` | `{{pendiente}}` |
   | `En curso` | `{{en_curso}}` |
   | `Cerrada` | `{{cerrada}}` |

6. Cambie **Título** a `Solicitudes por estado ({{total}})` y seleccione **Guardar**.

El widget muestra los números reales. `{{columna}}` se reemplaza por el valor de esa columna en la primera fila.

![Stacked Stat con el título Solicitudes por estado (49) y la leyenda Pendiente 12, En curso 7, Cerrada 30](/dashboards/stat_stacked/bar.png)

<Callout type="warning">
**Cuidado:** si el widget muestra **Error: No se pudieron cargar los resultados** justo después de agregar la consulta guardada, recargue la página. El servidor ejecuta la consulta desde el dashboard guardado, y el guardado automático tarda unos segundos.
</Callout>

<Callout type="info">
**Opciones de Fuente de Datos:**

| Opción | El widget lee |
| --- | --- |
| **Planificador** | Una consulta guardada del dashboard, elegida en **Variable** |
| **Estático (JSON)** | Datos escritos en el propio widget |
</Callout>

### Agregar la tabla de detalle

Una tabla lee **todas las filas** de su consulta. Una fila de la consulta es una fila de la tabla.

1. En **Ajustes › Conexiones › BigQuery**, cree otra consulta, `detalle_solicitudes`:

   ```sql
   SELECT
     id, estado, responsable,
     FORMAT_TIMESTAMP('%Y-%m-%d %H:%M', creada_en, 'America/Santiago') AS creada_en
   FROM `mi-proyecto.operaciones.solicitudes`
   WHERE (IFNULL(@estado, '') = '' OR estado = @estado)
   ORDER BY creada_en DESC
   LIMIT 500
   ```

2. Bajo **Parámetros** aparece el botón **Declarar @estado**. Selecciónelo. El parámetro queda con tipo `STRING`.
3. Deje el **Valor de prueba** vacío y seleccione **Ejecutar**. Vuelven todos los estados: la consulta recibe `NULL` e `IFNULL` lo trata como vacío.
4. Escriba `en_curso` en **Valor de prueba** y ejecute de nuevo. Vuelven solo esas filas.
5. Guarde la consulta.
6. En el dashboard, agregue una consulta guardada:
   - **Nombre del resultado**: `detalle`.
   - **Conexión**: su conexión de BigQuery.
   - **Operación**: `detalle_solicitudes`.
   - **Parámetros (JSON)**:

     ```json
     { "estado": { "kind": "filter", "key": "estado", "defaultValue": "" } }
     ```

7. Seleccione **Agregar Widget** y elija **Tabla de Datos V2**.
8. En sus ajustes, pestaña **Proveedor de Datos**, fije **Fuente de Datos** en **Planificador** y **Variable** en `detalle`. Debajo aparecen las columnas disponibles.
9. En la pestaña **Visualización**, revise **Columnas**: las columnas de ejemplo se reemplazan por `Id`, `Estado`, `Responsable` y `Creada En`. Cambie **Título** a `Detalle de solicitudes` y seleccione **Guardar**.

Si **Columnas** sigue mostrando las columnas de ejemplo (Vehículo, Cliente…), la consulta aún no se había ejecutado. Guarde, recargue la página y vuelva a elegir `detalle` en **Variable**.

`FORMAT_TIMESTAMP` convierte la fecha en texto. Sin él, la tabla muestra un `TIMESTAMP` de BigQuery como un número (`1.7933364E9`).

`@estado` es un parámetro de BigQuery. El vínculo `{"kind": "filter", "key": "estado"}` le da el valor del filtro `estado`, que crea en el paso siguiente. Mientras el filtro está vacío, el servidor envía `defaultValue` (`""`). La condición `IFNULL(@estado, '') = ''` deja pasar entonces todas las filas.

<Callout type="warning">
**Cuidado:** una consulta de BigQuery recibe siempre todos sus parámetros. No use `omitWhenEmpty` con BigQuery: si el parámetro se omite, la consulta falla. Use `defaultValue`.
</Callout>

### Filtrar la tabla por estado

1. Abra el menú de ajustes del dashboard y elija **Barra de Filtros**.
2. Seleccione **Agregar filtro** y complete:
   - **Tipo de filtro**: **Selección**.
   - **Etiqueta de visualización**: `Estado`.
   - **Clave de parámetro**: `estado`. Debe ser igual a `key` en el vínculo de la consulta. Si la deja vacía, se deriva de la etiqueta.
   - Active **Permitir una sola selección**.
   - **Origen de las opciones**: **Manual (escritas a mano)**.
   - **Opciones**: seleccione **Agregar opción** tres veces. **Etiqueta** es lo que ve el usuario; **Valor** es lo que recibe la consulta:

     | Etiqueta | Valor |
     | --- | --- |
     | `Pendiente` | `pendiente` |
     | `En curso` | `en_curso` |
     | `Cerrada` | `cerrada` |

3. Seleccione **Guardar** en el panel.
4. Desactive **Modo Edición**. El filtro aparece sobre los widgets como un botón **Estado**.

Abra **Estado** y elija **En curso**. La tabla se recarga y muestra 7 filas. La dirección de la página cambia a `?estado=en_curso`; puede compartir ese enlace con el filtro aplicado. El Stacked Stat no cambia porque su consulta no vincula el filtro `estado`. Así el resumen muestra siempre todos los estados.

![Dashboard con el filtro Estado: En curso, el Stacked Stat con los tres estados y la tabla con 7 filas en curso](/dashboards/tutorial/result.png)

<Callout type="info">
Hacer clic en una parte de la barra del Stacked Stat no filtra la tabla. El filtro de la barra de filtros es la forma de hacerlo.
</Callout>

### Compartir el dashboard

1. Abra el menú de ajustes y elija **Control de acceso**.
2. Seleccione **Gestionar permisos**.
3. Busque a su colega en **Usuarios**, elija el rol **Lector** (Consumer) y seleccione **Añadir**.

Su colega puede abrir el dashboard y usar el filtro, pero no puede cambiarlo. Para que pueda editar, asígnele **Editor**. En la interfaz, Lector, Colaborador, Editor y Administrador son los roles Consumer, Contributor, Editor y Coordinator.

</Steps>

## Qué construyó

| Pieza | Lee | Forma de la consulta |
| --- | --- | --- |
| Stacked Stat | La primera fila de `resumen` | Una fila, una columna por estado |
| Tabla de Datos V2 | Todas las filas de `detalle` | Una fila por solicitud |
| Filtro `estado` | — | Entrega un valor al parámetro `@estado` |
