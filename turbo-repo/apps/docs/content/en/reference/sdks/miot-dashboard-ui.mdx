# Dashboard UI

`@microboxlabs/miot-dashboard-ui` renders dashboard documents in React and other web frameworks using the shared dashboard contract.

**Status: unreleased workspace candidate.** Build the package or use a candidate tarball; these APIs are not a claim that an npm release is available.

## Choose an integration

- The self-contained `./browser-charts` entry adds chart registries to native HTML/Web Component hosts without host React; the chart engine stays optional and host-owned.
- The opt-in React chart registry binds both chart families to static or named saved-query results, templates, date filters and color rules; denied queries dispose stale charts.
- `ChartEngineView` manages host-engine creation, option replacement, resizing and disposal, including React Strict Mode.
- Mixed chart options preserve dual axes, line/bar/scatter combinations and per-series settings; both Next.js chart families use the public builders.
- The optional `./charts` entry builds original chart options for line, bar, scatter, pie and gauge; hosts retain the engine, date formatting and color-rule policy.
- Custom chart tooltips compile once and render as text, with correct source-row mapping for filtered pie and colored scatter points.
- `ChartCard` provides a themed chart container with host toolbar/chart slots and resize cleanup; the host supplies its chart engine.
- Both chart families share rolling date-range filters with an optional host clock and the existing inclusive cutoff behavior.
- Shared chart palettes preserve existing chart colors and isolate each dashboard’s color array; chart rendering remains host-owned.
- **React and Next.js:** use the React entry for rendering, document state, filters and saved-query providers. Keep session and server credentials in the host's backend.
- **Plain HTML or another framework:** use the self-contained browser runtime with `mountDashboard`. Update the instance when host state changes and destroy it when its container is removed.
- **Web Components and LiveView:** explicitly register the custom element and pass configuration through its JavaScript property. Keep the mount container outside host DOM patching and clean it up in the host lifecycle.

The browser runtime bundles its own rendering dependencies; a host does not need to install React. Load the package's scoped stylesheet once. Hosts can override the documented theme tokens.

## Implemented capabilities

The package provides a widget registry, grid/canvas primitives, text, percentage, circular and progress statistic renderers, template binding, filters and saved-query results. Query results support cancellation and bounded concurrency. Document state carries revisions and preserves drafts after conflicts.

The portable registries accept static data, template/provider values and named saved-query results. Legacy direct datasource configurations require migration to server connections and saved queries. These registries are not the entire app widget catalog, settings suite or backoffice.

Table and list row controls provide instance-local filtering and numeric-aware sorting over authorized results without mutating source rows.

Controlled filter and sort toolbars expose selected states, localized directions and keyboard controls with scoped light/dark styles.

Portable cell content supports literal and multiline text, badges, signed numbers and accessible progress, including safe color rules.

Column template helpers compile keys, headers and dynamic cell types with isolated helper engines and row/count context.

Typed column filters support text, numeric, date, enum and boolean result fields, with type detection and combined selections.

The active column filter summary provides accessible removal buttons, clear-all and host-supplied translations and value formatting.

Portable typed filter inputs provide debounced text/numeric editing, date ranges, searchable native checkboxes and isolated boolean radio groups. Hosts supply translations and own the popover lifecycle.

The portable column filter popover manages focus, Escape/outside dismissal and viewport positioning, with a host-selectable portal container and theme.

Shared action models normalize table/list links and restrict navigation schemes, including obfuscated executable URLs. Hosts validate resolved templates and retain destination authorization.

The portable action dropdown displays validated resolved links with native keyboard navigation, focus restoration and scoped light/dark styling.

The presentational data table renders shared cells with sticky edge columns, an action column, host-provided headers and loading/error/empty states. Both Next.js table variants use it, including resizable columns and row navigation.

The data-table registry composes saved-query or static rows with templates, filtering, sorting and safe actions in React and the browser runtime. Both original and resizable table registries are available; they are viewers and do not provide document editing or widget settings.

CSV export uses displayed rows and resolved labels, protects spreadsheet formula prefixes and supports browser downloads or a host delivery callback.

Resizable table width logic is shared with Next.js, preserving local viewer widths, explicit edit commits and saved-width restoration, with interrupted-drag cleanup.

The portable row context dialog validates resolved links, clamps to the viewport, manages keyboard focus and dismisses on outside interaction. The resizable Next.js table uses it.

The shared table renderer optionally supports pointer resizing, keyboard width adjustment and auto-fit, with local viewer widths and explicit host persistence.

Primary row links and secondary context actions use validated resolved URLs, with native keyboard links and action buttons. Alternating row backgrounds respect configured color rules.

The resizable registry renders existing `data_table_v2` widgets with saved widths, header sorting, row navigation and local viewer resizing in React and framework-independent browser hosts.

The shared data-list card renders titles, badges, metric grids and footer fields with the same safe cell formatting as tables. The Next.js list consumes it; hosts can supply real action controls.

The portable list registry renders saved `data_list` widgets from static or named saved-query rows, with card layout validation, filter pills, sorting, CSV export and safe actions. Legacy arbitrary-URL modes require migration to server queries.

Editable grids protect native and accessible controls from widget dragging, while preserving draggable backgrounds and nested-grid isolation. Hosts can reuse the same drag-cancellation selector.

The shared status statistic displays resolved text and optional host icons with validated border, icon and value colors. The Next.js adapter retains its existing template and color-rule behavior.

## Run the embedded example

The [standalone example](https://github.com/microboxlabs/modulariot/tree/trunk/turbo-repo/examples/dashboard-ui-standalone) includes a browser host and a Node proxy. It renders billing results from a configured dashboard server and supports service selection, refresh and a searchable host table.

Its README describes preparing the built UI assets, configuring the server and Consumer identity, and mounting private key/access files. The table and summary belong to the example host; the three embedded widgets come from the library.

Incomplete action drafts remain editable. Invalid row slots remain empty instead of promoting secondary navigation; resolved destinations are checked by the renderer.

The portable status registry resolves static or saved-query templates and applies border, icon and text rules. Hosts provide localized states and optional decorative icons; no icon dependency is bundled.

The icon statistic renderer supports horizontal and stacked text layouts, container-based scaling, and host-supplied icons and rich descriptions. Next.js retains its data and Markdown providers while sharing the presentation.

The portable icon registry binds templates to static or saved-query values, applies color rules and supports safe viewer links. Hosts can provide formatting, icons and sanitized rich descriptions without adding framework dependencies.

The shared sensitive statistic masks values until reveal and resets disclosure when its data or identity changes. Hosts supply translated controls; masking is visual privacy and does not replace server authorization.

The portable sensitive registry resolves static or saved-query templates, formats values by locale and applies text thresholds after reveal. Loading and failure clear disclosure; restored data starts masked again.

The stacked statistic uses lightweight SVG bars or donuts with a text legend and native segment tooltips. Labels stay literal, colors are validated, and the Next.js widget shares this renderer without a direct chart-library dependency.

The portable stacked registry resolves each saved item’s label and value through static or saved-query templates, supports both chart layouts, and clears stale segments during loading and errors.

The shared expandable statistic uses translated native disclosure controls, semantic detail fields, validated colors and independent state per instance. Hosts can reset expansion when dashboard identity changes.

The portable expandable registry resolves main and detail templates, applies text/background rules, and removes stale details during loading and errors. Recovered query results start collapsed.

The shared detailed statistic displays period comparisons, conditional colors and accessible target progress. Hosts supply formatted values and translated labels; the Next.js adapter retains query and field-comparison rules.

The portable detailed registry resolves saved-query amounts and comparisons, including field-based color rules. Hosts control number formatting and translated progress summaries; loading and errors clear stale amounts.

The shared sparkline statistic renders a lightweight SVG trend with optional accessible host summaries. Missing samples leave gaps and extreme values stay within finite geometry; Next.js retains its data and threshold handling.

The portable sparkline registry resolves configured sample templates and scalar values from static data or saved queries. It clears stale trends on loading/errors and does not invent history when samples are absent.

The shared information card supports nested widgets, host icons and styling, authorized edit controls and validated web links. The Next.js adapter retains its hybrid data-provider templates and color rules.

The portable information-card registry resolves provider and saved-query templates, preserves nested widgets, and clears stale links on loading or errors. Hosts provide icons and authorized editing actions.

## Security boundary

The server enforces tenant, scope and document permissions. Never put signing keys, database credentials or service-account keys in browser configuration. The example proxy allows only its configured read operations; it is a private demo access gate, not production SSO.

The current Handlebars compiler requires `unsafe-eval` in script CSP. Evaluate that constraint before embedding in a host with a strict CSP. No strict-CSP compatibility is claimed.

[Full API reference](https://github.com/microboxlabs/modulariot/blob/trunk/turbo-repo/packages/miot-dashboard-ui/README.md) · [Dashboard server](/en/operations/dashboard-server) · [Shared contract](/en/reference/sdks/miot-dashboard-contract)

`SettingsPanel` from `/react` provides keyboard-accessible settings tabs, a host footer and a save action gated by `isDirty` and `disabled`. The host supplies translated labels and owns validation, permissions, persistence and dismissal.

`useSettingsDirty`, `DirtySettingsProvider` and `useDirtySettings` share unsaved form state without app dependencies. Use one provider per form and unregister save callbacks on unmount; dismissal and confirmation remain host responsibilities.

`QueryBindingSelector` from `/react` binds widgets to host-supplied named results and displays their schema. It preserves unavailable bindings visibly, supports translated labels and read-only mode, and performs no discovery or query execution.

`SavedQueryEditor` from `/react` edits connection-backed query definitions using a host-approved connection/operation catalog and shared-contract parameter validation. It defaults to read-only; hosts own permissions, discovery and persistence. See the package README for draft lifetime and callback requirements.

`useDashboardState().setQueries` validates saved-query definitions and unique IDs/names, then updates the controlled document through its permission and undo/redo boundary. It returns false when denied or invalid.

`SavedQueryManager` composes controlled query selection, creation, editing and confirmed removal. Connect its boolean `onChange` to `useDashboardState().setQueries`; host rejection retains the draft. Write controls require explicit editing permission.
