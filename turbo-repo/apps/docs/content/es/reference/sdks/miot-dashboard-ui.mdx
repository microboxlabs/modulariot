# Dashboard UI

`@microboxlabs/miot-dashboard-ui` renderiza documentos de dashboard en React y otros frameworks web usando el contrato compartido.

**Estado: candidato del workspace sin publicar.** Compile el paquete o use un tarball candidato; estas APIs no implican que exista una versión publicada en npm.

## Elegir una integración

- La entrada autónoma `./browser-charts` agrega gráficos a hosts HTML/Web Component sin React del host; el motor sigue siendo opcional y administrado por el host.
- El registro opcional de gráficos React conecta ambas familias con datos estáticos o consultas guardadas, plantillas, filtros de fecha y reglas de color; consultas denegadas liberan gráficos anteriores.
- `ChartEngineView` gestiona la creación del motor del host, reemplazo de opciones, redimensionado y liberación, incluido Strict Mode de React.
- Las opciones mixtas conservan ejes duales, combinaciones de líneas/barras/dispersión y ajustes por serie; ambas familias de Next.js usan los generadores públicos.
- La entrada opcional `./charts` genera opciones del gráfico original para líneas, barras, dispersión, circular e indicador; el host conserva el motor, formato de fechas y reglas de color.
- Los tooltips personalizados se compilan una vez y se muestran como texto, conservando la fila de origen en gráficos circulares filtrados y puntos de dispersión con color.
- `ChartCard` ofrece un contenedor de gráficos con tema, espacios para controles y gráfico del host, y limpieza de observadores; el host aporta el motor de gráficos.
- Ambas familias de gráficos comparten filtros de fecha relativos con reloj opcional del host y el límite inclusivo existente.
- Las paletas de gráficos compartidas conservan los colores existentes y aíslan el arreglo de cada dashboard; el renderizado de gráficos sigue a cargo del host.
- **React y Next.js:** use la entrada React para renderizado, estado del documento, filtros y proveedores de consultas guardadas. Mantenga la sesión y las credenciales del servidor en el backend del host.
- **HTML u otro framework:** use el runtime de navegador autocontenido con `mountDashboard`. Actualice la instancia cuando cambie el estado del host y destrúyala al retirar su contenedor.
- **Web Components y LiveView:** registre explícitamente el elemento personalizado y pase su configuración mediante la propiedad JavaScript. Excluya el contenedor de montaje de los parches DOM del host y límpielo en su ciclo de vida.

El runtime de navegador incluye sus dependencias de renderizado; el host no necesita instalar React. Cargue una vez la hoja de estilos del paquete. El host puede personalizar las variables de tema documentadas.

## Capacidades implementadas

El paquete incluye registro de widgets, primitivas de grilla/canvas, renderizadores de texto, porcentaje y estadísticas circulares y de progreso, plantillas, filtros y resultados de consultas guardadas. Las consultas admiten cancelación y concurrencia limitada. El estado del documento conserva revisiones y borradores después de conflictos.

Los registros portables admiten datos estáticos, valores de plantillas/proveedores y resultados de consultas guardadas con nombre. Las configuraciones de datasource directo requieren migración a conexiones y consultas guardadas del servidor. Estos registros no constituyen el catálogo completo de widgets, configuraciones ni backoffice de la app.

Los controles de filas para tablas y listas ofrecen filtrado y ordenamiento numérico por instancia sobre resultados autorizados, sin modificar las filas originales.

Las barras controladas de filtros y ordenamiento exponen selección, dirección traducida y controles de teclado, con estilos claros y oscuros acotados.

El contenido portable de celdas admite texto literal y multilínea, badges, números con signo y progreso accesible, con reglas de color seguras.

Los helpers de plantillas de columnas compilan claves, encabezados y tipos dinámicos de celda con motores aislados y contexto de fila y cantidad.

Los filtros tipados de columnas admiten texto, números, fechas, enums y booleanos, con detección de tipos y selecciones combinadas.

El resumen de filtros activos ofrece botones accesibles para eliminar filtros, limpiar todos y textos y formatos proporcionados por el host.

Los editores portables ofrecen texto y números con actualización diferida, rangos de fechas, casillas nativas con búsqueda y grupos de opciones booleanas aislados. El host proporciona traducciones y gestiona el popover.

El popover portable de filtros gestiona foco, cierre con Escape o interacción exterior y posición en la ventana, con contenedor y tema elegidos por el host.

Los modelos compartidos normalizan acciones de tablas/listas y restringen protocolos, incluidas URLs ejecutables ofuscadas. El host valida las plantillas resueltas y conserva la autorización del destino.

El menú portable de acciones muestra enlaces resueltos validados, con navegación nativa por teclado, restauración de foco y estilos claros/oscuros acotados.

La tabla presentacional muestra celdas compartidas con columnas fijas, acciones, encabezados del host y estados de carga/error/vacío. Ambas tablas de Next.js la utilizan, incluidos anchos redimensionables y navegación por fila.

El registro de tablas combina filas estáticas o de consultas guardadas con plantillas, filtros, ordenamiento y acciones seguras en React y navegador. Están disponibles los registros original y redimensionable; son visores y no incluyen edición de documentos ni configuración de widgets.

La exportación CSV utiliza las filas visibles y etiquetas resueltas, protege prefijos de fórmulas y permite descarga en navegador o entrega mediante callback del host.

La lógica de anchos redimensionables se comparte con Next.js: conserva ajustes locales del visor, confirmación explícita de edición y restauración de anchos guardados, con limpieza de arrastres interrumpidos.

El diálogo contextual portable valida enlaces resueltos, limita su posición a la ventana, gestiona el foco de teclado y cierra con interacción exterior. La tabla redimensionable de Next.js lo utiliza.

La tabla compartida admite redimensionamiento por puntero, ajuste por teclado y ancho automático, con cambios locales del visor y persistencia explícita del host.

Los enlaces principales y las acciones contextuales de filas usan URLs resueltas validadas, con enlaces nativos y botones accesibles por teclado. Los fondos alternos respetan las reglas de color.

El registro redimensionable muestra widgets `data_table_v2` con anchos guardados, ordenamiento por encabezado, navegación por fila y ajustes locales en React o hosts de navegador independientes del framework.

La tarjeta compartida de listas muestra títulos, badges, métricas y campos de pie con el mismo formato seguro de las tablas. La lista de Next.js la utiliza; el host puede proporcionar acciones funcionales.

El registro portable muestra widgets `data_list` con filas estáticas o consultas guardadas, validación del diseño de tarjetas, filtros, ordenamiento, CSV y acciones seguras. Los modos antiguos de URL arbitraria requieren migración a consultas del servidor.

Las grillas editables excluyen controles nativos y accesibles del arrastre de widgets, manteniendo fondos arrastrables y aislamiento de grillas anidadas. El host puede reutilizar el mismo selector de cancelación.

La estadística de estado compartida muestra texto resuelto e iconos opcionales del host con colores validados. El adaptador de Next.js conserva sus plantillas y reglas de color.

## Ejecutar el ejemplo embebido

El [ejemplo standalone](https://github.com/microboxlabs/modulariot/tree/trunk/turbo-repo/examples/dashboard-ui-standalone) incluye un host de navegador y un proxy Node. Muestra resultados de facturación desde un servidor de dashboards configurado y permite seleccionar servicios, actualizar y buscar en una tabla del host.

Su README explica cómo preparar los archivos del paquete compilado, configurar el servidor y la identidad Consumer, y montar los archivos privados de acceso y firma. La tabla y el resumen pertenecen al ejemplo; los tres widgets embebidos provienen de la biblioteca.

Los borradores de acciones incompletos siguen siendo editables. Las posiciones de fila inválidas quedan vacías sin promover acciones secundarias; el renderizador valida los destinos resueltos.

El registro portátil de estado resuelve plantillas estáticas o de consultas guardadas y aplica reglas al borde, icono y texto. El host proporciona estados traducidos e iconos decorativos opcionales; no se incluye una dependencia de iconos.

El indicador con icono admite diseños de texto horizontal o apilado, escalado según el contenedor e iconos y descripciones enriquecidas del host. Next.js conserva sus proveedores de datos y Markdown y comparte la presentación.

El registro portátil de indicadores con icono conecta plantillas con datos estáticos o consultas guardadas, aplica reglas de color y permite enlaces seguros en modo lectura. El host puede proporcionar formato, iconos y descripciones enriquecidas saneadas sin dependencias de framework.

El indicador sensible compartido oculta el valor hasta que se revela y restablece la ocultación al cambiar sus datos o identidad. El host proporciona controles traducidos; la ocultación visual no sustituye la autorización del servidor.

El registro portátil sensible resuelve plantillas estáticas o de consultas guardadas, formatea valores según la configuración regional y aplica umbrales al texto revelado. La carga y los errores restablecen la ocultación; los datos recuperados vuelven a mostrarse ocultos.

El indicador apilado utiliza barras o anillos SVG ligeros con una leyenda textual y descripciones nativas por segmento. Las etiquetas son literales, los colores se validan y el widget Next.js comparte este renderizador sin depender directamente de una biblioteca de gráficos.

El registro portátil apilado resuelve la etiqueta y el valor de cada elemento guardado mediante plantillas estáticas o de consultas guardadas, admite ambos diseños y elimina segmentos anteriores durante la carga y los errores.

El indicador expandible compartido utiliza controles nativos traducidos, campos de detalle semánticos, colores validados y estado independiente por instancia. El host puede restablecer la expansión al cambiar la identidad del dashboard.

El registro portátil expandible resuelve plantillas del valor principal y sus detalles, aplica reglas al texto y fondo, y elimina detalles anteriores durante la carga y los errores. Los resultados recuperados comienzan contraídos.

El indicador detallado compartido muestra comparaciones entre períodos, colores condicionales y progreso accesible hacia la meta. El host proporciona valores formateados y etiquetas traducidas; el adaptador Next.js conserva las consultas y las reglas de comparación entre campos.

El registro detallado portátil resuelve importes y comparaciones de consultas guardadas, incluidas reglas de color basadas en campos. El host controla el formato numérico y los resúmenes de progreso traducidos; la carga y los errores eliminan importes anteriores.

El indicador sparkline compartido representa una tendencia SVG ligera con resúmenes accesibles opcionales del host. Las muestras ausentes dejan espacios y los valores extremos mantienen coordenadas finitas; Next.js conserva los datos y umbrales.

El registro sparkline portátil resuelve plantillas de muestras configuradas y valores escalares desde datos estáticos o consultas guardadas. Elimina tendencias anteriores durante carga/errores y no inventa un historial cuando faltan muestras.

La tarjeta de información compartida admite widgets anidados, iconos y estilos del host, controles de edición autorizados y enlaces web validados. El adaptador Next.js conserva las plantillas híbridas de proveedores de datos y las reglas de color.

El registro portátil de tarjetas de información resuelve plantillas de proveedores y consultas guardadas, conserva widgets anidados y elimina enlaces anteriores durante carga o errores. El host proporciona iconos y acciones de edición autorizadas.

## Límite de seguridad

El servidor aplica permisos de tenant, scope y documento. Nunca incluya claves de firma, credenciales de base de datos ni claves de cuenta de servicio en la configuración del navegador. El proxy del ejemplo permite únicamente las lecturas configuradas; es un acceso privado para demostración, no SSO de producción.

El compilador actual de Handlebars requiere `unsafe-eval` en la CSP de scripts. Evalúe esta restricción antes de integrar en un host con CSP estricta. No se afirma compatibilidad con CSP estricta.

[Referencia completa de API](https://github.com/microboxlabs/modulariot/blob/trunk/turbo-repo/packages/miot-dashboard-ui/README.md) · [Servidor de dashboards](/es/operations/dashboard-server) · [Contrato compartido](/es/reference/sdks/miot-dashboard-contract)

`SettingsPanel` de `/react` ofrece pestañas de configuración accesibles por teclado, un pie controlado por el anfitrión y una acción de guardado condicionada por `isDirty` y `disabled`. El anfitrión proporciona las etiquetas traducidas y controla validación, permisos, persistencia y cierre.

`useSettingsDirty`, `DirtySettingsProvider` y `useDirtySettings` comparten el estado de cambios pendientes sin dependencias de la aplicación. Use un proveedor por formulario y elimine los callbacks de guardado al desmontar; el cierre y la confirmación son responsabilidad del anfitrión.

`QueryBindingSelector` de `/react` vincula widgets a resultados con nombre proporcionados por el anfitrión y muestra su esquema. Conserva visibles los vínculos no disponibles, admite etiquetas traducidas y modo de solo lectura, y no realiza descubrimiento ni ejecución de consultas.

`SavedQueryEditor` de `/react` edita consultas basadas en conexiones mediante un catálogo autorizado por el anfitrión y validación de parámetros del contrato compartido. El modo predeterminado es solo lectura; permisos, descubrimiento y persistencia pertenecen al anfitrión. Consulte el README para el ciclo de vida del borrador y los callbacks.

`useDashboardState().setQueries` valida las consultas guardadas y la unicidad de sus identificadores y nombres, y actualiza el documento controlado mediante sus permisos e historial de deshacer/rehacer. Devuelve false si la actualización no está permitida o es inválida.

`SavedQueryManager` integra selección, creación, edición y eliminación confirmada de consultas controladas. Conecte su callback booleano `onChange` a `useDashboardState().setQueries`; un rechazo del anfitrión conserva el borrador. Los controles de escritura requieren permiso explícito de edición.

`PermissionAssignmentEditor` edita un borrador controlado de permisos con identidades autorizadas por el anfitrión y roles del contrato compartido. Es de solo lectura por defecto, conserva identidades ausentes del catálogo y evita agregar duplicados. El anfitrión controla el guardado explícito mediante el cliente de permisos, la actualización de capacidades y el aislamiento de sesión; la autorización del servidor sigue siendo obligatoria.

`useDashboardPermissions` conecta ese flujo de borrador con el cliente del servidor: consulta capacidades antes de cargar permisos, valida el reemplazo y recarga el estado autorizado, bloquea la edición ante errores de autorización y cancela solicitudes al cambiar recurso o sesión. El anfitrión mantiene el guardado explícito y el reinicio del borrador; consulte el README para la semántica de reemplazo y fallos de recarga.

### Permisos en el espacio de Next.js

La página del dashboard del servidor usa el editor y el hook portables de permisos. Abra **Administrar permisos** cuando el servidor otorgue esa capacidad. Ingrese el ID exacto de usuario o grupo de su proveedor de identidad, selecciónelo, elija un rol y agréguelo al borrador. Revise la lista completa y confirme **Guardar cambios**. Este formulario no busca en un directorio ni valida que el ID exista; la escritura y las mayúsculas deben coincidir con la identidad del servidor. Las asignaciones existentes se conservan hasta editarlas o eliminarlas explícitamente.

El guardado reemplaza las asignaciones locales y luego las recarga. Los permisos del ámbito y del propietario siguen vigentes; eliminar una asignación local no revoca esos otros permisos. Recargue explícitamente después de un error, incluso si la escritura pudo completarse antes de fallar la recarga. Cerrar o recargar un borrador modificado requiere confirmación. El anfitrión Next usa su proxy autenticado y vinculado a la organización; el editor reutilizable no depende de ese proxy ni de Alfresco.
